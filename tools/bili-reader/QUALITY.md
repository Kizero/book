# 如何判断有没有丢内容

本工具现在是本地采集与校验脚本，加当前 AI 对话中的阅读整理。它有可重复使用的程序，但尚未成为输入 BV 后独立完成全部分析的服务。

## 四个容易混淆的层次

| 层次 | 做到了什么 | 仍然不能证明什么 |
| --- | --- | --- |
| 原始材料保存 | 视频、已取得的字幕或本地 ASR、截图、时间戳留在本地 | ASR 没听错、抽帧没漏掉画面 |
| 片段归属校验 | 每段已有文字分入一个真实章节，引用 ID 存在 | 章节文字保留了每段的重要意思 |
| 内容单元记录 | 逐项登记论点、推导、例子、条件、纠正及其去向 | 内容清单本身是完整的，AI 语义判断必然正确 |
| 理解验证 | 用户闭卷复述、解释反例或预测变体 | 单凭报告完成就能证明用户已学会 |

“原文还在”和“摘要无损”是两个不同命题。没有可靠的全量语义真值时，不报告“100% 内容保留率”。

## 阅读产物

1. **速读主线**：允许压缩重复输入、停顿、无新增信息的重述，帮助决定哪里值得展开。
2. **详细讲义**：恢复问题、论点、为什么成立、例子怎样支持、限定条件和现场纠正。口头讲述、投影补注、整理者解释、额外查证分别标明。若讲师明确说明部分投影由 AI 添加，应保留这一来源属性，不把投影上的每句话都当成讲师口述。
3. **内容覆盖记录**：每个已识别单元有真实片段 ID、必要截图和讲义位置。非关键旁枝若省略，必须留下原因。关键例子、反例、条件与纠正不能因“主题相似”被删除。
4. **个人增量**：在前三项之后执行；有旧笔记也只能证明已有记录。遇到新的前提、范围、证据或反例时仍保留。原始材料和详细讲义不因增量过滤而删除。

## 表达检查

按 [READ_VIDEO.md 的表达要求](READ_VIDEO.md#表达要求精准直白通俗易懂) 检查所有阅读产物：

- 读一遍，能否知道谁在做什么、为什么这样做？抽象概念有没有用普通话讲清楚？
- 一句里塞了几层意思？需要拆句或分条时，有没有拆开？
- 话说得更短、更直白后，前提、范围、反例、不确定性和来源是否仍然准确？
- 有没有只为显得有力而添加的口号、排比或绝对判断？删掉这些话，保留实质内容。

## 与现成讲义比较

比较对象是另一份可供查错的材料，不是自动真值。逐项比较主题、核心论断、推导、例子、限定和来源：

- 原视频能确认的：进入本次讲义，并给时间定位。
- 只在参考讲义出现的：回看原视频；仍无法确认时标成参考讲义的补充或待核实内容。
- 原视频出现而参考讲义未展开的：保留，并说明新增的是内容覆盖，不是用户一定不知道的新知识。
- 两者冲突的：记录冲突和能支持各自的证据，不用篇幅或语气决定正确性。

本次先阅读了参考讲义再分析视频，所以属于有参考材料的对照改进，不是盲测，也不能拿一致程度当作独立准确率。

第二条视频发现的具体例子：参考讲义把结尾“墙内超人”解释为系统规格边界，原视频口述与画面却指向算力集中造成的社会分隔；研究失败段落的投影 AI 补注也不能替代讲师讲述的真实工具与超时搜索路径。这些差异记录在 `runs/BV1CQt365EzW-p1/coverage-review.html`。它们说明，只有“每段转录都有章节归属”还不够，必须检查具体意思与来源层级。

## 用量怎样算

下载、FFmpeg 和本地 Whisper 不调用文字模型 API；本地 Whisper 本身仍然是 AI 模型。讲义理解、视觉判读、个人笔记比对与质量判断需要模型参与。已有结果再次打开不需要重新推理。

`usage_audit.py` 从显式指定的本地 Codex 日志中只导出某一轮任务的计数，不复制对话正文。按响应 ID 去重、逐次求和，再与该任务累计记录核对。不要把旧 `token_count` 显示快照的差额当成唯一账本：上下文压缩后，它可能与实际逐响应用量不一致。

缓存输入包含在输入里；推理输出包含在输出里；它们不能再额外加到总量上。整轮任务的累计量包含反复携带的上下文与工具开发，不能当作文本材料大小，也不能直接等同于账户扣费。

对于只验证过一两条视频的原型，目前没有可靠的“平均每视频 token 数”。降低成本的方向是：缓存一次采集与通用讲义；后续个人阅读只重算增量；将工具研发与读视频分开；只把当前阶段所需的证据送进模型。每个阶段的实际用量需要继续实测，不能先承诺一个低数值。
