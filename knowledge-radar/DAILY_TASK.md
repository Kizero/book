# 每日信息雷达任务

## 0. 执行入口与完成检查（2026-09-08 修正）

自动唤醒的目标是执行当天交付，不是重答历史消息中的“把它纳入每日任务”。2026-09-08 曾已启动采集却转去确认配置，导致空交付；上下文恢复后先检查当天成品，继续缺失环节，不能凭旧用户消息或任务 ACTIVE 状态结束。

开工与最终回复前各运行一次 `python3 check_delivery.py --date YYYY-MM-DD`（日期按北京时间）。开工返回 NOT_READY 是正常的待办信号，应继续工作。日报、中文文件、导入档案、实际书库副本未核对前不得宣称全部完成。

入库后创建 `state/deliveries/YYYY-MM-DD.json`：date、status=ready、entity_id、book_id、book_title、readback=[beginning,middle,end]，以及 report/record/chinese/import_record 四个文件各自的 path（相对雷达根目录）与 sha256。先实际回读再记录，不伪造证据。检查器只证明本地成品一致，不证明译文质量、云同步或消息已送达。检查通过后仍须最终发送当天主题与报告链接，不能仅说“任务已开启”。

确有障碍则保存 status=blocked 与具体 blocker，照常发送已有日报和缺口；不能把 blocked 改成 ready 绕过检查。应用若停在用户未保存的编辑框，不替用户保存或取消，记录导入待补。每次后续运行先补齐已生成但未导入的阅读件，再决定是否需要新发现，避免重复推荐。

每天都要交付一份有用的雷达，帮助用户发现值得读的材料，并借助 AI 更快理解、检验和运用。默认从长期兴趣前沿发现一个主对象；阅读债务增加时也要保持每日交付，通过分层阅读和消化已有材料控制负担。

开始前读取：

- `config/discovery.json`：主题前沿、发现通道、评分和成品要求；
- `config/sources.json`：已知高信号入口和核验来源；
- `state/index.json`、`state/discovery_state.json` 和 `state/feedback.jsonl`：个人基线、近期使用过的主题与反馈。

## A. 先发现，不围着昨天打转

主题排除（用户于2026-09-15指定）：以后不再收录重点讲“合作”的材料。评分前按核心问题排除合作原则、团队协作、科研合作、合作关系经营等主题，不生成阅读件或导入LocalReader，也不以复习名义再次推送。只是顺带提到合作、核心仍是其他知识或技术问题的材料，不作关键词误杀。已有材料和批注保留，不追溯删除；用户明确点名时按当次要求处理。对应规则见 `config/discovery.json` 的 `selection.topic_exclusions`。

1. 按 `topic_cursor` 轮换两个主题，按 `lane_cursor` 轮换两个发现通道；不要默认沿最近一次 featured 对象继续搜索。
2. 每个“主题 × 通道”至少形成两个候选。候选可以来自人物文章、访谈和评论中的明确引用，也可以来自课程书单、领域史、口述史、奖项资料、反例史和相邻领域桥梁。
3. 评论只承担引用发现、纠错和跨领域桥接；热度不是质量证据，也不把整个平台评论区爬成语料库。
4. 新发现候选过滤 `known/reading/read/ignored` 实体和 30 天内已经 featured 的对象。若没有可信增量，明确说明，并交付标注为“复习 / 知识连接”的内容：围绕已有材料给出一个理解问题或实际应用。复习不冒充新发现，不修改对象状态来绕过去重。
5. 按个人新颖度、相关性、来源质量、桥接价值和全文可得性评分，只选择一个主对象进入下一阶段。

6. 对初选对象，以作品要回答的具体问题查询最新个人依据：`/Users/houguanqun/dsh/local-reader/scripts/learning evidence --question '具体问题与关键词'`。查询要含论点或机制，不能只用作者名；需要指定主题时先用 `learning topics` 取得准确标题。将实际 Markdown 输出保存到 `inbox/` 下本轮独立的 `YYYY-MM-DD-personal-context-HHMMSS.md`，同名时换新文件；后续不得覆盖报告已引用的快照。根据读者真实原话、未解问题及对具体回答的理解自报，校正“为什么值得读”和候选增量，必要时更换主对象。自报只针对一条回答，既不表示赞同，也不能推导为整本作品 `known/read`。书籍反馈仍从 `state/feedback.jsonl` 读取，两类状态不自动互相改写。接口失败时记录缺口，继续依现有来源交付；无检索结果时保持个人基线未知。每次新交付重新查询，旧快照仅用于解释旧报告的依据。

## B. 再围绕作品做一份阅读入口

1. 先获取作品本身或足以判断的原始材料；摘要不能替代作品。
2. 补充作者生平中会改变作品理解的部分，以及作品的成因、时代处境和要回答的问题。
3. 从作品本身提取核心论证与可迁移的判断工具，不把信息系统的方法冒充作品的方法。
4. 至少加入一个有分量的反例、过时判断或强批评。
5. 如果存在合法免费全文，实际打开检查一个可用版本；保存本地副本或稳定链接。
6. 书目、出版社和版本核验只收在简短资料说明中，除非版本差异本身会影响理解。

## C. 入库、检查、生成

1. 将原始材料或必要摘录写入 `inbox/`，保留 URL、采集时间与证据位置；不要绕过登录、付费墙或访问限制。
2. 创建 `records/*.json`。用 `about_entity` 把背景卡、作品方法和资源绑定到本次主对象；原作者观点、历史事实和你的迁移推断要分开标记。
3. 运行 `python3 radar.py validate`；失败就修复，不生成看似完成的日报。
4. 运行 `python3 radar.py rebuild` 和 `python3 radar.py report --date YYYY-MM-DD`。
5. 成功后更新 `state/discovery_state.json` 的游标、查询和 featured 历史。

日报正文保持克制：一个主对象，一份可读的来龙去脉，三到四条来自作品本身的收获，一组反例或批评，以及一个可立即打开的阅读入口。

## D. 每日交付与掌握

1. 每天北京时间 09:00 由“每日知识雷达”自动任务触发，在本对话交付。没有新材料也发送复习或知识连接内容；失败则发送具体障碍和已完成范围，不静默跳过。
2. 每期给出分层入口：约 3—5 分钟理解问题与核心观点；约 15—20 分钟阅读最关键原文；只有值得深入时再建议完整阅读。时间是估计，随材料与阅读速度调整。
3. 每期给两个不直接泄露答案的理解问题，以及一个可选的小型应用。回答后的纠错或实践结果才是掌握证据，读了摘要、点击链接和表示准备读都不能算掌握。
4. 材料推荐不自动变成待办。明确建议“知道即可 / 读关键段落 / 值得精读”，并说明原因；只有用户选择投入时才推进阅读队列。
5. 每周选一天在正常发现之外做简短消化回顾：连接本周观点、删除重复建议、指出仍未理解的问题。未收到阅读反馈时写明进度未知，不虚构阅读完成或催促清空队列。
6. 如当天已经交付，避免重复发送同一份内容；按用户反馈继续讨论即可。借助 AI 提速的目标是能解释、能质疑、能应用，而不只是读完更多摘要。

## E. 中文原文阅读件与 LocalReader 导入（2026-09-07 起）

用户要求：后续获取主对象原文，优先准备中文译文并自动导入 LocalReader；书库只导入中文版，不额外导入英文副本。这一步是每日执行的一部分，不是仅提供操作建议。

1. 先判断全文获取及翻译条件。优先用户直接提供的文件、公版作品或明确许可全文翻译的材料；公开可读、GitHub 可下载不自动等于可完整翻译。不能处理全文时明确说明并请求用户提供原文文件，不绕过付费或访问限制，不用摘要顶替译文。已有中文原文直接使用，已有译文须有可用的合法来源。
2. 中文阅读件保留原文顺序、标题层级、论证、例子、问答、必要脚注与图表，不压缩成导读。文件首页简短标明原作者、来源链接、版本、AI 翻译身份和覆盖范围；正文只保留中文，必要专名、公式和代码可原样保留。评论与导读独立于译文。
3. 在 library/ 保存命名清楚的中文版 Markdown，按原文章节检查覆盖，抽查数字、否定、限定条件与术语。全文过长需分批时显式标明未完成部分，不把节译命名为全文。原始来源及对应关系留在后台档案，无须把英文再放进书库。
4. 使用 localreader-reading 技能读取最新接口。先以 learning books 或实际书库界面核对重复；有受支持的文件导入接口时优先使用，否则经原生“导入书籍”界面导入。不要猜测 CLI 参数，不直接编辑应用数据库，不擅自修改应用代码。2026-09-07 已观察到原生导入入口；当时 learning --help 没有列出书籍导入命令，后续可重新检查。
5. 导入后必须在书库确认中文标题，打开检查正文开头、中段和结尾；可用 learning books 获取实际 book ID。保存 imports/ 下的导入记录：对象、来源、译文路径与哈希、覆盖范围、实际 book ID（取得时）、导入时间及回读结果。重跑先核对记录和书库，不重复导入，不覆盖旧批注或已有不同版本。
6. 日报交付说明“中文版已导入 LocalReader”仅限导入和回读成功；否则分别报告原文获取、翻译、导入中的实际障碍。雷达本身仍按时交付。导入不等于开始阅读，更不等于已掌握；不自动修改 reading/read 状态。
