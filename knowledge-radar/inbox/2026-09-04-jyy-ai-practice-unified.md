# 蒋炎岩老师的 AI 实践与核心判断（统一总纲）

记录日期：2026-09-04

记忆地位：这是后续讨论蒋炎岩老师 AI 实践时的统一主入口，融合 2026-09-03 的“AI 实践与核心判断”和“从白板 Agent 到完整生态”两份记录；旧记录保留为细节证据。内容来自用户现场转述，尚未对照原视频或讲义核验。

## 一、总判断：使用 AI 是不断“解锁”能力边界

AI 像一个读过大量材料、甚至读过许多冷门材料的交流者。人与 AI 合作不是掌握一份固定功能清单，而是不断感知它能做什么、做到什么程度，再带着它去完成此前做不到的更大任务。想象力决定能看到哪些新可能；判断力、架构能力和验证能力决定这些可能能否成为可靠现实。

人的作用不能只概括为“提需求”。更准确地说，人负责选择值得解决的问题，发现隐藏控制面，限制规格空间，选择抽象和中间表示，设计证据链与完成条件，并把 AI 推向它尚不能独立跨越的边界。

## 二、完整能力栈：从白板 Agent 到可托付系统

统一演进链路是：

白板 Agent 通用推理 → domain-specific 插件提供稳定观测和操作 → Agent 探索并完成一次任务 → 成功轨迹沉淀为可检查、修改、重放的脚本 → Harness 管理状态、权限、重试、验证与恢复 → IR/架构保证语义正确、变化局部和跨后端复用 → 渲染器、应用软件或机器把描述兑现为结果。

可用一个乘法式理解能力：推理 × 可观测性 × 可操作性 × 反馈。任何一项接近零，整体都会失败。即使单步成功率 99%，连续 100 步全部成功也只有约 36.6%，所以“能做一次”与“能放心托付”之间隔着完整的可靠性工程。

浏览器不应只当作像素和按钮，而应看作包含 DOM、Network、事件、状态机和 CDP 等稳定控制面的工程系统。电脑也应优先寻找专用控制面。domain-specific 插件的本质是把巨大、模糊的动作空间压缩成语义窄、稳定、可验证的操作。插件不在于多，而在于接口是否像 Unix pipe 一样窄、稳定、可组合。

## 三、个人智能操作系统

通用闭环是：现实材料数字化并保留原始凭证 → 结构化、可检索、可定位 → AI 结合通用知识和个人历史 → 过滤已知信息、提取增量 → 生成行动或交付物 → 工具执行 → 自动验证 → 人只在最窄的高风险接口判断。

代表实践包括：现代化终端；在 U 盘安装操作系统并用 QEMU 验证；研究 PPT 提示词；邮件和附件自动落库归档；检索历史回复和判断方式，以本人口吻生成草稿；保存发票；通过 Apple Reminders 接收结果，也反向向 Agent 发指令，例如打印当天发票。核心资产不是 AI 会写一封邮件，而是系统能检索本人过去如何判断、如何回应。

工作流可以自举：观察或录屏日常操作 → 发现重复模式 → 生成自动化 → 回放验证 → 人确认 → 收集新异常 → 再改进。稳定、可描述、可验证的重复劳动，本质上是尚未抽象出来的程序。

## 四、知识工作：从摘要转向增量、证据和对抗

学习新领域时，可以先让 AI 交付一个完整、可运行的整体，再沿真实问题向下理解。第一层理解可能不如亲手从零搭建深，但效率远高于在缺少上下文时逐块学习；后续必须通过证据、实验和主动回忆补深。

深度阅读不等于摘要，而包括：追踪结论和证据并能跳回原文；寻找遗漏前提、反例和作者可能的最强反驳；合上原文接受口试，再依据原文纠错；重新组织观点，并连接到旧笔记和真实问题。阅读《A Philosophy of Software Design》时，还要求从历史教训和事故、人类历史中公认且高影响力的相关工作、第一性原理三个方向展开。多个子 Agent 可以像“抽卡”一样产生不同思路，由主 Agent 和人判断，即用算力换智力。

论文 review 的高效方式是：先把人类已有知识当作基线，再剥离论文相对基线真正新增的部分；拿不同层级的总结、论证结构和原文互相检查。AI 读 B 站视频时，以 BV ID 获取音频 transcript，并在画面差异显著时截图，生成图文时间轴；结合“AI 耿同学”式个人记忆，删除已经掌握的内容，只保留可信的增量信息。

## 五、CS Professional 的杠杆：现场制造工具

Agent 不应只用于完成作业。CS 的优势是知道计算机世界存在哪些协议、状态、接口和可编程控制面，能够把一次性自然语言需求“编译”为可重复执行的工具。可编程性的边界不只是有没有 API，而是能否找到可控输入、可观测输出与可判定完成条件。

在 ehall 上，先让 Agent 探索页面、理解流程并成功一次，再把轨迹沉淀为脚本，对应 Programming by Demonstration。昂贵推理只付一次，重复执行趋近低成本；成功一次只是 demo，可检查、修改、重放和验证后才是软件资产。

考试统分流水线体现“机器承担吞吐、人驻守高风险接口”：照片作为原始凭证，离线模型识别姓名、学号和小分；系统反序报出姓名、学号和求和算式，由老师复核并写总分；结果进入 Excel 模板，最后登记到教务系统。“反序 + 报算式”类似航空管制 readback，用不同表示制造冗余，截获错位、漏项和误识别。

## 六、重新解释基础设施：Everything Is Code

远程桌面传文件的 QRCode 方案体现了重新解释系统的能力：Excel 是可编程显示设备，鼠标是输入线路，二维码动画是发送信道，水平或垂直抖鼠标可编码反向信道。QRCode 已有同步和 Reed-Solomon 纠错；再加入帧号、校验、ACK/NAK 和重传，就能在 Raw Socket 式协议上发送复杂文件。“网卡”只是网络的一种实现，协议需要的是能够承载符号的媒介。

Everything Is Code 的含义不是所有东西最终都是源代码文本，而是视频、论文、零件都可以先变成可复制、可修改、可验证的控制描述。视频的脚本、分镜、素材、时间线和字幕，论文的问题、证据、实验、图表与可复现构建，现实物品的 CAD、仿真、BOM、固件和 G-code，都是不同中间表示；渲染器、排版系统、CNC 或 3D 打印机是不同后端。从 bits 到 atoms，Agent 可以生成描述，机器负责兑现。

## 七、最重要的反例：跑出来不等于做成

不能因为 AI 能做每个局部，就直接让它“造航母”。产品完成度是系统性乘法：若 10 个环节各有 90% 可靠性，整体成功率约 35%。AI 提高单点产能，不会自动消除接口、协作、运营和维护风险。

`QRcode.xlsx` 的短需求隐藏了巨大的规格空间：字符编码、Base64、分片顺序、二维码容量、空串与超长输入、F9 重算、计时和循环播放语义等。验收不能只是“文件可打开”或某个样例能扫描，而应表达为端到端性质：对任意输入 s，扫描各帧并按协议拼接，再 Base64 解码，必须恢复原始 `bytes(s)`。

初版模型生成了约 2 MB、硬编码且无法维护的 Excel。它把需要处理所有输入的程序问题偷换成“让某个特定输入通过”。AI slop 的本质不只是体积大，而是变化没有局部性：一个需求变化迫使整张表重新生成。成功演示不是实现需求。

真正转折不是让模型再多想或生成更多，而是设计架构：公式模板和工作表结构相对输入长度保持 O(1)，只有数据、必要计算量和帧数随输入 O(n) 增长。架构检查题是：输入从 1 KB 增至 10 KB 时，究竟哪些部分在问题本质上必须增长？

最终通过一个可在 Python 执行、又可翻译到 Excel 的 IR 或小语言建立基础设施。Python 端验证 Base64、分片、二维码像素和端到端性质；Excel 端验证兼容性与翻译语义保持。这把一个巨大的“是否碰巧能跑”问题拆成可独立验证的语义层、翻译层、宿主兼容层和端到端性质。

## 八、长期应保留的核心结论

1. 使用 AI 是能力解锁，不是固定功能消费。
2. 个人历史中的判断、回应和偏好，比孤立提示词更接近核心资产。
3. 白板 Agent 只是起点；插件、脚本、Harness、IR、验证和恢复共同决定能否托付。
4. Agent 探路、脚本接管：一次成功必须沉淀为可检查、可修改、可重放、可验证的资产。
5. 深度阅读要保留原文定位、证据链、对抗阅读、主动回忆和增量提取。
6. 先交付再理解可以提高学习效率，但不能省略后续验证和理解深化。
7. 软件工程的核心是控制规格、选择抽象、保持变化局部，并建立可判定的验收性质。
8. 人最不可替代的工作是选择问题、重新解释系统、设计结构与证据链、承担价值和风险判断，并带着 AI 推进未知边界。
